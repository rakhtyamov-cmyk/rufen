# Предложения по улучшению campaign-dashboard

Ничего из этого не реализовано — это roadmap на обсуждение. Сгруппировано по областям,
внутри каждой — примерно по приоритету (быстрые и ценные вещи сверху).

Легенда усилий: 🟢 малое (часы) · 🟡 среднее (день-два) · 🔴 большое (новая инфраструктура/архитектура)

---

## 1. Данные — самое ценное, разблокирует остальное

- [ ] 🔴 **Убрать ручной paste-merge.** Сейчас данные обновляются вставкой Slack-дайджеста/лога
  и мёрджем скриптом в scratchpad. `manage.gs` должен сам писать JSON (или в Google Sheet — см.
  паттерн `ua-weekly-dashboard`) на каждый прогон. Это отдельная инженерная работа на стороне
  `.gs`, но именно она превращает прототип в живой инструмент — см. README «Путь к продакшену».
- [ ] 🟡 **Реальный `campaignId`.** Ссылки «Открыть» сейчас ведут по синтетическому id
  (`customerId + индекс`) — почти всегда не туда. Нужно тянуть настоящий id из GAQL в `manage.gs`
  и прокидывать в JSON.
- [ ] 🟡 **История по дням, не один снимок.** Каждый мёрдж перезаписывает предыдущее состояние.
  Растущий лог (JSONL/таблица/БД, по одной записи на кампанию на прогон) открывает:
  - **дельты** — стрелка вверх/вниз рядом с ROAS/tROAS относительно вчера;
  - **тренд-график** вместо одной sparkline по инсталлам — то же самое по ROAS/бюджету за N дней;
  - **diff-режим**: «что изменилось с прошлого прогона» (новый NOT_ELIGIBLE, закрытый Д1) —
    ровно то, что мы вручную вычисляли на глаз при последнем обновлении.
- [ ] 🟢 **Автообновление.** Сейчас `fetch('/api/campaigns')` дёргается один раз при загрузке.
  Простой `setInterval` + refetch (или SSE, если появится push от бэкенда) — данные не протухают
  без ручного reload.

## 2. UX-полировка ✅ сделано

- [x] 🟢 **Пустое состояние под `onlyAttention`.** Когда фильтр «Только требуют внимания» —
  единственный активный и дал 0 совпадений, показывается «Отлично, ничего не требует внимания»
  вместо общего «попробуйте изменить фильтры»; если активны ещё и другие фильтры — общее сообщение
  остаётся честным (см. `App.jsx`, `hasOtherFilters`).
- [x] 🟢 **Фильтры/сортировка в URL query params.** `src/lib/useFilterState.js` — единый объект
  состояния (`q`/`actions`/`account`/`geos`/`sort`/`attn`), синхронизируется в URL через
  `history.replaceState` (не `pushState` — иначе каждая буква в поиске плодит запись в истории).
  Ссылку с текущим срезом теперь можно скинуть коллеге как есть.
- [x] 🟢 **Persist в localStorage.** Свёрнутые аккаунты — `src/lib/useLocalStorageSet.js`,
  переживают reload. Фильтры сознательно остались в URL, не в localStorage — так они шарятся
  ссылкой, а не только живут в браузере того, кто их выставил.
- [x] 🟡 **Multi-select по гео.** `Filters.jsx` → `GeoMultiSelect` на `DropdownMenuCheckboxItem`
  (Radix DropdownMenu) — выбор нескольких стран разом, кнопка показывает «Гео (N)».
- [x] 🟡 **Radix Select вместо нативного `<select>`.** Аккаунт и сортировка теперь на
  `src/components/ui/select.jsx` (Radix Select, тот же паттерн, что и остальные shadcn-примитивы).
- [x] 🟢 **Переключатель темы.** `src/lib/theme.jsx` (`ThemeProvider`/`useTheme`) + кнопка
  `ThemeToggle.jsx`: `light`/`dark`/`system`, персистится в localStorage, в режиме `system` живо
  реагирует на смену темы ОС. `tailwind.config.js` переведён на `darkMode: 'class'`.
- [x] 🟢 **Loading-скелетон.** `DashboardSkeleton.jsx` — контур шапки/тайлов/health bar/карточек
  вместо текста «Загрузка…».
- [x] 🟢 **Клавиатурные шорткаты.** `/` — фокус на поиск (если не печатаешь в другом поле),
  `Esc` — сброс всех фильтров разом (кроме свёрнутых аккаунтов — это отдельная настройка вида,
  не фильтр).

Всё проверено вживую (build без ошибок, консоль чистая, URL/localStorage переживают настоящий
reload страницы, multi-select и Select провалидированы через полную последовательность pointer-
событий — Radix слушает `pointerdown`, не голый `click`).

## 3. Новые фичи

- [ ] 🟡 **Кнопка «Скопировать как Slack-дайджест».** Форматирует текущий отфильтрованный вид
  обратно в тот же markdown, что постит `manage.gs` — удобно для ручной отправки/цитирования в
  тред, когда прогон сделан вне расписания.
- [ ] 🟡 **Экспорт в CSV** отфильтрованного списка — для быстрого шаринга в Sheets/Excel.
- [ ] 🟡 **Сравнение снимков** (вчера/сегодня): выбрать два прогона из истории (см. п.1), показать
  таблицу дельт по ROAS/tROAS/статусу — естественное продолжение «истории по дням».
- [ ] 🔴 **Отметки менеджера** («видел», «в работе», «отклонено с комментарием») — требует
  бэкенда с записью (сейчас всё read-only). Даже localStorage-заглушка на первое время закроет
  часть ценности без сервера.
- [ ] 🟢 **Кнопка «Копировать имя кампании»** рядом с тултипом-разбором — сейчас имя видно
  полностью (только что починили truncate), но скопировать можно только вручную выделением.

## 4. Инженерка / надёжность

- [ ] 🟡 **Юнит-тесты для `src/lib/*`.** `actions.js` (`needsAttention`), `format.js`
  (`parseCampaignName`/`daysAgo`), `nameTokens.js` (`describeSegment`) — чистые функции без React,
  тестируются тривиально. По аналогии с тем, что уже сделано для `manage.gs` в
  `google-ads-management/tests/` (harness грузит реальный код в песочницу) — тот же принцип
  применим и здесь.
- [ ] 🟢 **Error boundary.** Сейчас необработанное исключение в дереве компонентов даёт белый
  экран без объяснения. React `ErrorBoundary` + сообщение «что-то сломалось, см. консоль» — дешёвая
  страховка.
- [ ] 🟢 **ARIA-полировка.** Базовая доступность есть (фокус-ринги, `tabIndex`, `aria-pressed` на
  тоггле), но не проходили целевой a11y-аудит (screen reader на карточках/тултипе, контраст на
  кастомных status-цветах в реальных сочетаниях). Дёшево прогнать `axe-core` разово.
- [ ] 🟢 **Code-splitting**, если бандл вырастет. Сейчас ~250KB JS — некритично для внутреннего
  инструмента на 54 кампании, но при росте датасета/фич стоит держать в уме `React.lazy` для
  истории/тултипа.

## 5. Деплой / доступ (если решите перестать быть локальным прототипом)

- [ ] 🔴 **Хостинг.** Уже отмечено в README — Cloud Run/аналог, CI на `npm run build`.
- [ ] 🔴 **Аутентификация.** Дашборд показывает реальные бюджеты/ROAS по кампаниям — как только
  это не `localhost`, нужен хотя бы базовый доступ (Google SSO по домену компании, например).
- [ ] 🟡 **Секреты/конфиг.** Сейчас `data/campaigns.json` лежит прямо в репозитории — приемлемо
  для прототипа с демо-данными, но при переходе на реальный пайплайн (п.1) это станет живым
  бизнес-данными в git-истории. Нужен `.gitignore` на `data/` + подключение через API/переменные
  окружения.
